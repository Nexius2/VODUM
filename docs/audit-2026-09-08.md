# Audit VODUM du 8 septembre 2026

Audit de l'état local du projet, y compris les modifications non commitées. Aucun fichier applicatif existant n'a été modifié. Les essais fonctionnels utilisent une base temporaire, un serveur fictif et des comptes fictifs.

## Conclusion

Deux bugs applicatifs ont été reproduits. Aucun autre plantage n'a été observé dans les parcours de lecture exercés. Les contrôles automatisés couvrent de nombreux services, mais ne permettent pas de certifier l'absence de bugs en production.

## Bugs confirmés

### P2 — Une reconnexion termine prématurément l'assistant d'installation

- Fichiers : `app/routes/auth.py:513`, `app/core/setup_wizard_state.py:40`. Le même manque de données apparaît dans les requêtes de connexion Plex, `app/routes/plex_auth.py:607` et `:646`.
- Scénario : installation en cours, serveur déjà ajouté, étape 5, puis reconnexion administrateur.
- La requête de connexion ne charge pas `wizard_state_json` ni `wizard_completed`. `should_resume_setup_wizard()` interprète donc l'état comme une ancienne installation sans progression et marque l'assistant comme terminé dès qu'un serveur existe.
- Reproduction sur la vraie route locale : `POST /login/submit` retourne `302 /` et transforme les indicateurs en `wizard_active=0, wizard_completed=1`, alors que `wizard_step=5`.
- Conséquence : les étapes de configuration restantes sont sautées lors de la reconnexion. Les données ne sont pas supprimées, mais l'installation est déclarée terminée à tort.
- Correction recommandée : charger les paramètres complets de l'assistant dans les parcours de connexion, ou les relire dans le service de reprise. Ajouter une régression au niveau de la route pour une installation interrompue après l'ajout du serveur.

### P2 — Un identifiant PayPal mal formé provoque une erreur 500

- Fichier : `app/core/payment_links.py:135`, appelé par `app/routes/portal_admin.py:223`.
- Scénario : paiements expérimentaux activés, formulaire de configuration PayPal avec l'identifiant `https://[paypal.me/test`.
- `urlsplit()` lève `ValueError: Invalid IPv6 URL`, sans traitement dans `_paypal_username()` ni dans la route.
- Reproduction avec une session administrateur et un jeton CSRF valide : `POST /settings/portal/payments` retourne **500**.
- Conséquence : une erreur de saisie interrompt l'enregistrement au lieu d'afficher une validation. L'exception intervient avant la transaction de remplacement des liens.
- Correction recommandée : retourner une validation négative lorsque l'analyse de l'adresse lève `ValueError`, puis vérifier l'affichage de l'erreur et la conservation des liens existants.

## Anomalies dans les vérifications et le déploiement

1. **Deux tests dépendent d'une date devenue ancienne.** `tests/test_portal_sessions.py:71` et `tests/test_portal_admin_data.py:25` créent des sessions le 24 août 2026, puis certaines vérifications utilisent l'heure réelle. Leur durée de 14 jours est dépassée le jour de cet audit. Cela explique les assertions de session valide/active en échec ; ce n'est pas la preuve d'un défaut d'expiration en production. Utiliser une horloge cohérente pour toute la vérification.
2. **Un test pollue les imports des autres tests.** `tests/test_migration_library_mappings.py:29` retire inconditionnellement des modules de `sys.modules`, même lorsqu'ils existaient avant ses simulations. Le test du contrat de mot de passe Jellyfin réussit seul, mais échoue dans la suite complète avec une tentative de connexion à `jf.test`. Restaurer les modules préexistants au lieu de les retirer systématiquement.
3. **Documentation incomplète.** Les validateurs du README et de la documentation MkDocs échouent sur l'absence de `VODUM_ADMIN_PUBLIC_URL`, présent dans `.env.example`. Documenter son rôle dans la séparation des hôtes administrateur/portail.
4. **Environnement de test différent des dépendances Docker.** Python local : 3.12.14. Huit des dix dépendances directes ne correspondent pas aux versions de `requirements.txt` : Flask 3.0.3 au lieu de 3.1.3, plexapi 4.17.0 au lieu de 4.18.2, pytz 2024.1 au lieu de 2026.3.post1, waitress 3.0.0 au lieu de 3.0.2, croniter 2.0.7 au lieu de 6.2.4, requests 2.32.3 au lieu de 2.34.2, websocket-client 1.8.0 au lieu de 1.9.0 et cryptography 43.0.1 au lieu de 50.0.1. `pip check` réussit, mais ne vérifie pas l'alignement avec ce fichier. Rejouer les contrôles dans l'environnement exact de déploiement.
5. **Pas de barrière de tests dans le workflow de publication inspecté.** `.github/workflows/docker-image.yml` construit et publie l'image sans lancer la suite Python. Ajouter une étape bloquante une fois les tests rendus fiables.

## Limites et traces

Pas de navigation visuelle dans un navigateur, de test de charge multi-utilisateur, de construction Docker ni d'essai avec de vrais serveurs Plex/Jellyfin, SMTP, Discord ou reverse proxy. Les API externes restent simulées ; les données et les secrets de l'instance réelle n'ont pas été utilisés pour ces reproductions.

Le chargement et la compilation des pages ne valident pas toutes les interactions JavaScript. Les tests de bootstrap utilisent le schéma livré, pas un échantillon de chaque ancienne version de base de données.
